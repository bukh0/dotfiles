## Additional notification audit (2026-10-14)

Two failures were reproduced before fixing them:

- `components/NotificationPopup.qml`: a new critical alert could evict an older critical alert while ordinary cards remained. Eviction now prefers already-closing cards, then the oldest ordinary card, and only then the oldest critical card. The same policy applies when reducing the visible-card limit. Eviction only hides the popup; history remains available.
- `components/NotificationDaemon.qml`: `restoreTimestamps("null")` accepted valid JSON of the wrong shape, then notification delivery threw when reading a timestamp. Restoration now accepts only object maps with finite, nonnegative timestamps within the JavaScript Date range. Invalid entries fall back to a fresh timestamp.

The offscreen reload test emits the expected missing-backend warning for Quickshell's own reload popup; history restoration and replacement checks pass. The normal saved-state path remains covered. ## Connection hold, picker refresh, and defensive bounds

- NetworkService holds only password submissions, publishing the owning output before enabling submittingPassword. Saved/open-network connections remain hover-only. ControlPanel transfers the hold to any retry prompt and permits explicit dismissal; cancellation checks active ownership rather than matching an empty inactive screen field. Both close guards use heldByUser; close delay remains 510ms.
- MusicWidget clamps the page index against the live model count. MusicService now publishes a stored, read-only selectedIndex after reconciling the model and fallback selection. User selections update immediately from the rendered model, guarded during synchronization. Model row signals still occur incrementally; this is not an atomic ListModel replacement.
- Picker listing/thumbnail refreshes coalesce while pending. Follow-up runs are deferred until exit handling (and collected listing output) completes; failed startup releases pending state. Work queued for a page that is no longer active is discarded.
- SysmonService checks normal exit code and crash status before reporting a power-profile failure.
- Validation: tests/run.py passes both profiles and all 22 focus checks. New picker_refresh.py verifies newly discovered wallpapers and thumbnails plus one coalesced rerun; picker_async.py covers missing executables and late errors. profile_exit.py exercises success, nonzero exit, and zero-code crash status without changing power settings. These tests do not reproduce compositor input routing or perform real Wi-Fi authentication.

Music publication tests (tests/music_sync.py): selection follows reorder/removal, empty models reset to zero, user selection is immediate, metadata preserves the index; index-change observers see the completed model. The main regression runner includes these checks.
