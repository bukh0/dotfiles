# Review — 2026-10-19

Opening the notification drawer now clears all active popups and queued popups,
including critical cards and cards already fading out. It does not close server
notifications, invoke actions or remove history rows. Incoming notifications do
not create popups while the drawer is open; closing the drawer does not replay
those notifications. Subsequent arrivals show normally.

Network background polling now considers the entire action lifetime, including
the gap between process exit and stderr completion. The monitor debounce also
rechecks this guard when its timer fires, preserving pending refreshes until the
action settles. The delayed-collector test asserts polling remains blocked.

Picker application processes stop their launch watchdog when started and check
failed launches after running becomes false, retaining the 500 ms fallback for
Quickshell versions that do not emit that transition. The watchdog is armed
before starting the process. Tests exercise missing theme and wallpaper helpers
as well as an application that starts and reports an error.

Two proposed regressions were not reproduced and did not need code changes:

- Quickshell 0.3.2 already calls `refreshToplevels()` during Hyprland IPC
  initialization. Client objects are populated from IPC, not exclusively from
  foreign-toplevel events. See the initialization callback in the
  [release source](https://raw.githubusercontent.com/quickshell-mirror/quickshell/v0.3.2/src/wayland/hyprland/ipc/connection.cpp).
  The existing fullscreen-event refresh remains necessary for mode changes.
- ListModel role changes notify the yielding binding on the installed Qt build.
  The hover regression now queues a notification *before* hovering the oldest
  card and checks that yielding immediately transfers to the next card without
  a queue/store revision change. It passed before any implementation change;
  adding a global `rev` increment would be redundant.

Validation: popup suite (25 cases), normal/delayed network command completion,
picker application and missing-helper tests, picker asynchronous lifecycle, and
main service/slider regressions. Tests use isolated fixtures and mock helpers.

## Fullscreen drawer follow-up

The notification drawer now closes when the bar becomes hidden on its screen,
including true fullscreen while pinned. Maximizing or entering fullscreen on
another monitor leaves it open. Leaving fullscreen does not reopen it. The
bar visibility suite loads the actual drawer bindings and passes all eight
cases, including both pinned and hover-open drawers and notification offsets.

No extra close-window refresh was added: Quickshell 0.3.2 handles `closewindow`
by removing the client from both the global and workspace models, and handles
`movewindowv2` by transferring it between workspace models. These operations
are explicit in the release source linked above. Popup suppression remains in
the popup component, preserving the daemon's notification signal contract.

## Desktop surfaces and live palette audit

Confirmed on the running Wayland compositor with brief isolated surfaces:

- An item tooltip creates no separate popup surface. Network and tray tooltips
  now use `Popup.Window`; the actual NetworkIndicator test receives a separate
  configured xdg-popup. See [Qt's popup types](https://doc.qt.io/qt-6/qml-qtquick-controls-popup.html#popup-type).
- A surface switched from None to OnDemand did not receive keyboard focus;
  switching to Exclusive did. ControlPanel now requests Exclusive focus only
  while open and held by the user (pinned or entering/submitting a password).
  The actual ControlPanel hover-to-pin transition receives `wl_keyboard.enter`.
  Hover-only panels retain None. Existing Qt focus tests cover Escape behavior.

`Colors.qml` now loads `components/colors.json` through FileView/JsonAdapter.
Theme installation atomically replaces JSON, not QML. The theme writer was
updated and rebuilt; all nine presets, Matugen's template/configuration, and
Pywal's template were migrated. Pywal's derived surface tints remain computed
from its background/foreground when the two JSON container values are empty.
Profiles, picker and clipboard link to the same JSON file. The shell's palette
watcher/reload timer is removed. The live palette test loads the real singleton,
replaces JSON through its profile symlink, recovers from malformed JSON, and
checks that the root is created only once. Manual/code reload restoration and
its tests remain necessary and are retained.

Additional changes:

- Defensive DND initialization always reaches `_dndReady`, including a thrown
  read error. Real missing-file/directory persistence tests pass, as does an
  injected exception test.
- Music excludes the playerctld proxy and keeps page order stable on playback
  changes, retaining the existing Spotify preference and selected-player ID.
- Picker screen selection is assigned once when opened.
- Sliders defer wheel input when their parent panel overflows; dragging remains
  available. Clock text remains a binding. The unused timeText model/delegate
  role and unused shell Wayland import were removed.
- A hide-button/default-action test passes without modifying tap handling.
  StyledText tests for `&apos;`, decimal/hex apostrophes and an astral numeric
  entity also pass unchanged on the installed Qt build.

Testing infrastructure now has a shared harness, explicit palette/MPRIS
transport stubs, and automatic suite discovery through `tests/run.py --all`.
MusicService is loaded unchanged instead of replacing its imports/enums in
source. `--live` explicitly enables desktop-surface tests. The local pre-commit
configuration runs core regressions; this workspace has no initialized Git
repository, so no hook was installed. Remaining source-transform fixtures are
not claimed to have been fully migrated.

Both native Bluetooth and Networking modules are present in the installed
build. Replacing their service backends, switching all outside-click masks to
HyprlandFocusGrab, and changing system authentication policy remain separate
redesigns. No failure in those existing paths was demonstrated here. In
particular, the power script writes specific CPU/GPU controls; a generic
passwordless shell or tee rule would not be an appropriate replacement for a
purpose-built privileged helper. No sudoers/polkit changes were made.

Validation outcome: all 40 discovered isolated suites passed across the broad
run and targeted rerun. The broad run caught a stale bar-test extraction marker
after removing the palette watcher; that fixture was corrected and its eight
cases passed. Both actual profile loads and the actual tooltip/panel Wayland
checks passed. Additional checks covered the installed Pywal template with its
real exporter, derived JSON surface tints, and a thrown DND read error. The
existing application exit behavior, notification reload tests and theme
installation rollback tests remain passing. No real network connections,
Bluetooth pairings, power changes or wallpaper changes were performed.
